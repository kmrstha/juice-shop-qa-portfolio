QUESTIONS AND POTENTIAL DEFECTS

Q-01: The password advice lists five rules but "12345" and "abcdefgh" are accepted, so none of the advice is enforced. Which is intended: the advice, the 5-40 character message or both? (BUG-01, REQ-REG-12)
Q-02: The password field stops input at 40 characters but the repeat password field accepts more. With 41 characters typed in both, "Passwords do not match" is shown and registration is blocked. (BUG-02, REQ-REG-07)
Q-03: Does the server reject a password longer than 40 characters when it is sent directly without the browser? To test with postman in the API testing project.
Q-04: VERIFIED — The Password counter shows "10/20" at 10 characters and "40/20" at 40; its denominator remains 20 despite the 40-character maximum. The Repeat Password field also shows a counter below the field in the form "entered/40". The Password counter discrepancy remains unresolved. (BUG-03, REQ-REG-18, REQ-REG-19)
Q-05: VERIFIED — After 15 consecutive failed login attempts, no account lockout, login delay or warning appeared. Whether lockout or rate limiting is intended remains an open security question.
Q-06: The Expiry Year field offers only years from 2080. A card expiring before 2080 cannot be entered. Is this range intended? (Potential defect, REQ-PAY-12)
Q-07: The Forgot Password fields show "/20" and accept at least 200 characters, while registration stops at 40. Is the length rule intended to differ? (Potential defect, REQ-FPW-16, REQ-FPW-17)
Q-08: Searching for characters shows different products whose names and descriptions do not contain it. Is this intended?
Q-09: Each review shows the author's email address to all visitors, including logged-out users. Is this intended?
Q-10: Link Image accepts a URL typed by the user. Which URLs are intended to be accepted? (Security observation, to review in the security part of the project.)
Q-11: Clicking Set with an empty username field removes the existing username with no message. Is this intended? (Defect candidate, REQ-PRF-05)
Q-12: The tracking page does not show the delivery status ("In Transit") that is shown in Order History. Should it? (Question, REQ-ORH-06, REQ-ORH-07)
Q-13: The tracking page shows "Bonus Points Earned: 0". Is 0 expected for this order? (Question, REQ-ORH-11)
Q-14: VERIFIED — Change Password accepts a new password identical to the current password. The application displays "Your password was successfully changed." Whether reusing the current password should be allowed remains an open question.
Q-15: The Data Export page lists PDF and Excel, but neither can be selected. Is this intended? (Defect candidate, REQ-EXP-04)
Q-16: The erasure form accepts any email address and any security answer, and the Delete User Data button is always enabled. Is verification of the email and answer intended? (Defect candidate, REQ-ERS-05, REQ-ERS-06)
Q-17: After a valid erasure request, the user can still log in and see their data. When does the erasure happen? (Question, REQ-ERS-09, REQ-ERS-10)
Q-21: VERIFIED — The Complaint form's Submit button remains enabled when the message contains only spaces, and clicking Submit successfully submits the complaint. This differs from the behavior described for Reviews and Feedback. (Potential defect, REQ-CMP-17)
